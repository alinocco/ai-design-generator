# Шаг 1. Распознавание плана: Обмерщик v0

`aidesign recognize plan.png --debug` превращает картинку маркетингового плана застройщика
в `plan.json` нашей схемы. Обучения и ручной разметки не нужно: это классическое CV плюс OCR.

```bash
uv sync --extra dev --extra recognition
uv run aidesign recognize data/raw_plans/IMG_1662.PNG --debug   # plan.json + картинка с наложением
uv run aidesign eval-recognition data/raw_plans                 # метрика по всей папке
```

## Как устроено

1. **Стены.** Тёмные малонасыщенные пиксели основного «стенового» тона. Морфологическое
   открытие маленьким ядром убирает тонкие линии: дуги дверей, рамы окон, мебель, текст.
   Цветные метки (красные и фиолетовые точки на сайте) отсекаются по насыщенности.
2. **Векторизация.** Маска → полигоны → отрезки стен с толщиной (`geometry.walls`).
3. **Проёмы.** От каждого свободного торца стены ищем соседнюю стену вдоль оси (окно,
   широкий проём) и поперёк (дверь у угла). Тип — по тонким линиям вокруг: рама в проёме → окно,
   дуга → дверь (с петлёй и стороной открывания), пусто → проём без двери.
4. **Помещения.** Watershed по свободной площади. Семена — подписи площадей, которые
   застройщик ставит в центре каждой комнаты, поэтому граница между комнатами ложится
   в самое узкое место — в дверной проём.
5. **Масштаб.** Подбираем мм/px так, чтобы с подписями совпало как можно больше помещений;
   одна неверно найденная комната масштаб не сбивает.

## Метрика без разметки

Застройщик подписывает площадь каждого помещения. Считаем долю помещений, у которых
площадь по распознанной геометрии совпала с подписью.

| Набор | Планов | Помещений с подписью | ±5% | ±10% |
|---|---|---|---|---|
| Стиль A (чёрные стены, `IMG_16xx`) | 16 | 84 | 58% | 65% |
| Стиль B (серые стены, мебель, `tg_image_*`) | 14 | 56 | 50% | 55% |
| Всего | 30 | 140 | 55% | 61% |

Падений нет ни на одном плане. Помещение, у которого подпись не прочиталась,
сливается с соседним — это тоже снижает метрику.

## Известные ошибки (по убыванию влияния)

1. **Открытая планировка.** Кухня и гостиная разделены только пунктиром → одна комната.
   Сумма площадей при этом совпадает с суммой подписей. Решение: при двух подписях в одной
   области делить её по пунктиру или по прямой между стенами.
2. **Лоджии и балконы.** Остекление нарисовано тонкими линиями, контур квартиры местами
   «протекает» или обрезается. Подписи балконов вида `0.3 (1)` пока игнорируются.
3. **Мелкие помещения в стиле B** (прихожая, кладовка, санузел рядом): тонкие перегородки
   и мебель путают watershed.
4. **Входная дверь** найдена не везде: её дуга часто лежит снаружи квартиры.
5. **Типы помещений** пока не определяются (`other`): нужна VLM или правило по значкам
   (ванна, унитаз, плита).

## Что дальше

- Пунктир как граница помещений и подписи балконов — должны дать заметный прирост на стиле A.
- Тип помещения через VLM: подать вырезку комнаты и спросить тип; координаты VLM не выдаёт.
- Экран подтверждения плана: исправления пользователя → эталон и метрика «правок до верного плана».
- Сравнение с базовой линией: VLM, которая сама читает план целиком.
